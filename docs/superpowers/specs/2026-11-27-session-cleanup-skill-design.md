# Session Cleanup 独立 Skill 设计

日期：2026-11-27
状态：已获用户确认

## 目标与背景

当前合并后清理规则位于 `roxis-way`，`auto-develop` 只提醒用户可以另行清理。此次将完整清理生命周期迁移到独立的 `session-cleanup` skill，使清理入口、检测、审批、执行和结果回读由同一套规则负责，并默认覆盖合并 PR 的远端与本地任务分支。

## 方案取舍

- 采用完整独立 skill：`session-cleanup` 负责清理计划与执行；`roxis-way` 只路由；`tapd-sync` 只提供已有绑定和工作项操作。这样只有一份清理清单和一套风险标准。
- 不采用仅拆分 Git 清理的方案：若审批和项目管理工作项仍留在 `roxis-way`，一次清理会继续跨越多个所有者，无法形成统一的风险清单。

## 范围

- 新增可隐式匹配合并后会话清理意图的 `session-cleanup`，保留各宿主显式调用方式。
- 更新 `roxis-way`、`auto-develop`、README、技能触发契约、Codex 行为探针及安装测试。
- 保留“先提交完整清理计划和准确命令，再等待明确批准”的安全边界；本任务不实际清理任何交付分支或数据。
- 不引入通用清理脚本、第三方依赖或新的运行时服务。

## 清理前检测

1. 通过托管平台确认 PR 状态确实为 merged，记录目标仓库、base、head 仓库与分支、PR head SHA 和 merge commit；closed 不等于 merged。
2. 通过只读远端查询确认任务头分支仍存在且仍指向已合并的 PR head。若合并后又有新提交，阻止删除。fork PR 必须删除 head 仓库的分支，不得误删 base 仓库分支。
3. 确认候选分支不是默认分支、base 分支或受保护分支；解析本地分支、上游和所有 worktree 的实际占用关系。
4. 检查已跟踪修改、暂存修改、未跟踪和忽略文件、未推送提交与分叉。未分类改动、未知归属文件或额外提交都必须阻止相应删除，不得使用强制命令绕过。
5. 文档、开发数据、任务服务、工作项和线程均须具有本任务归属证据；清理过程中发现新对象或需要更换命令时，停止并重新提交计划。

## 数据与文档处理

- 任务私有计划、研究报告、决策记录等文档迁移到主仓库根目录的 `.ai/session-archive/<delivery-id>/`，不得留在即将删除的 worktree 中。
- 归档前确认目标是主仓库内的隔离目录且被 Git 忽略。若 `.ai/session-archive/` 尚未被忽略，经计划批准后只向主仓库 `.git/info/exclude` 添加精确规则，不擅自修改跟踪中的 `.gitignore`。
- 正式产品文档、已进入合并 PR 或 base 的文档保持原位。归档不得覆盖已有文件；冲突时停止并重新规划。
- 审计证据、工作项绑定和待回读记录必须保留。只有可确认属于任务且可再生的缓存、日志或临时数据才可删除；未知、用户所有或不可再生数据保留并标注风险。

## 风险清单与执行

每项同时包含动作 tag 与风险 tag：`[LOW]`、`[MEDIUM]`、`[HIGH]`，安全门失败时另加 `[BLOCKED]`。动作使用 `[DELETE]`、`[MOVE]`、`[KEEP]`、`[TRANSITION]` 等明确标签，并列出检测证据、准确命令和恢复方式。

- 低风险：不覆盖原文件的归档移动、已确认可再生的任务临时数据。
- 中风险：全部检测通过后的任务 worktree、本地分支和远端头分支删除。
- 高风险：未推送或合并后新增提交、脏工作区、不可再生数据、归属不明对象；默认保留或阻止，不得随普通清理执行。
- 核心 Git、worktree 与文档清理默认作为一个整体：任一分支、工作区或归档安全门失败，整个核心清理都标记 `[BLOCKED]`；工作项等独立对象不可用时，仍可单独提交安全的本地清理计划。

经明确批准后，按清单依次完成任务所属服务停止、文档归档、数据清理、worktree 移除、本地与远端分支删除和工作项操作。每一步检查结果；平台工作项必须回读，不能把命令已发送当作成功。

## 实施与验证

1. 先增加 `session-cleanup` 元数据、静态安全规则及行为探针测试，运行并确认因 skill 尚不存在或规则未实现而失败。
2. 新增 skill 与 agent 元数据，迁移清理规则并更新相关路由、说明和测试契约。
3. 运行直接相关测试，再运行完整 `npm test`，覆盖 14 种 agent 的安装与发现。
4. 运行完整 `npm run verify`，其中包含已认证的 Codex 触发验证；若外部认证不可用，明确报告未完成的验证，不以单元测试代替。
5. 检查最终 diff 和 `git status`，删除验证产生的非必要文件，不提交、不推送、不创建 PR。
